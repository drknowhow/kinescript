# Kinescript

These notes are for any coding agent. The C3 block below applies only where the `c3_*` MCP tools are
installed; without them, use your usual file and shell tools.

JSON scenes in, video out.

- Setup: `pip install -e ".[dev]"`, then `python -m pytest`. On Linux, skia-python needs system libraries even
  with `KINE_BACKEND=cpu`; the README's Install section lists them. The maintainer's venv is `.venv` (Python 3.14):
  `.venv/Scripts/kine`, `.venv/Scripts/python -m pytest`.
- Engine: `kinescript/` — `timing.py` (cue references), `props.py` (keyframes, tweens, AST-checked expressions),
  `scene.py` (loading, components, sequences), `render.py` (Skia, GPU via hidden glfw OpenGL context, CPU fallback),
  `output.py` (parallel chunked ffmpeg encode + audio mix), `verify.py` (check/look/probe), `mcp.py`, `cli.py`.
- Frames must stay a pure function of (scene, frame number); `tests/test_core.py::test_frame_is_pure_function_of_index`
  guards it. Do not add state carried between frames.
- Before calling any visual change done: `kine check`, then `kine look --boxes` and look at the image.
- Launch video: `python marketing/build_promo.py <fps> <ms>` then `kine render marketing/promo.json -o docs/promo.mp4 -q high`.
  Numbers quoted in it, the README and site/ are measurements; re-measure before changing them.
- Brand: `brand/BRAND.md`. Theme defaults in `kinescript/components.py` THEME follow it.
- Sample media is generated (`python examples/make_media.py`) and gitignored.

# C3 — agent workflow

Use C3 for repository intelligence and audited changes:
1. Recall relevant project facts with c3_memory; inspect .c3/MAP.md.
2. Find candidates with c3_search; map with c3_read(file_path) (no symbols), then
   read exact symbols or lines with c3_read. Check shared changes with c3_impact.
3. Edit with c3_edit, validate with c3_validate, and record decisions with
   c3_session(action='log'). Preserve unrelated work.
4. Use c3_shell for commands and c3_shell_job for long work; outputs already
   have a safety budget. Use c3_filter for other long logs.
5. Snapshot with c3_session before clearing or handing off unfinished work.

If a C3 tool fails or its scope is insufficient, explain the limitation and
use a targeted native fallback. Never bypass an access denial or masked path.
A [c3-access:confirm] response is a hold: follow its S8 instructions, wait on
the existing request with c3_override, and retry only after approval. A pending
request is not a denial. Agent-config writes must go through c3_edit.
